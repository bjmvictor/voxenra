## AAA 偏白的核查

在各自中央解剖区域内，以 max(R,G,B)>35 排除背景后粗略统计：

| 统计 | 小赛看看 | 当前 AAA |
| --- | ---: | ---: |
| 平均 R / G / B | 150.09 / 110.02 / 86.04 | 166.00 / 148.99 / 133.98 |
| 近白像素比例 | 1.68% | 12.46% |
| 暖色像素比例 | 85.74% | 41.28% |

“近白”定义为最小通道 >210 且通道差 <25；“暖色”定义为 R−B>35 且 R>G。
这些是画面外观诊断，分母取各图自身可见像素，不能当成临床质量、准确率或相同组织的测量。
截图尺寸与投影不同也会影响统计，但结果与可见的偏白现象一致。

代码中的 AAA 来自 Slicer CT-AAA，214.389 HU 处的 RGB 已是 (1,1,1)，
214～419 HU 一段保持接近白色且透明度较高；这不是小赛看看同名模板的完整参数。
因此优先调整这段颜色及透明度过渡，而不是给整个图像加色偏或只降低曝光。
代码位置：`src/qt_dicom_viewer/volume_ct_presets.py:29`。

## 表面条纹诊断

当前步长是最小体素间距，即 0.9766 mm，未启用 jitter。
在保持相机、AAA 参数和源数据完全相同的实验中：

- 步长减至 0.4883 mm：部分密集细纹减弱。
- 步长减至 0.24415 mm：条纹进一步减弱，表面更连续。
- 只开启 jitter：规则条纹减弱，但有明显颗粒感。
- 半步长加 jitter：噪声有所减轻，仍不能仅凭一张图选为默认。

这说明可见条纹至少部分来自射线离散采样，不能把全部细纹当作稳定结构。
切片间距为 3 mm，降低射线步长不会补回采集时没有的层间信息。
后续应评估固定质量下更小步长的性能与多数据集效果。
VTK 的 [jitter 说明](https://vtk.org/doc/nightly/html/classvtkGPUVolumeRayCastMapper.html)
也将其用途描述为减轻木纹状采样伪影。
代码位置：`src/qt_dicom_viewer/ui/volume_render_backend.py:176`。

## 调窗实验

每次从重置后的 AAA 开始，重新应用相同缩放。
参考软件垂直拖动 71、水平拖动 106 个截图坐标单位，约为视口对应边长的 10%。
当前实现垂直拖动 70、水平拖动 85 个逻辑像素，严格等于对应边长的 10%。

当前得到的 WL / WW：

| 动作 | WL | WW |
| --- | ---: | ---: |
| 默认 | 281.646 | 276.18 |
| 上拖 10% | 309.26 | 276.18 |
| 下拖 10% | 254.03 | 276.18 |
| 右拖 10% | 281.65 | 303.80 |
| 左拖 10% | 281.65 | 248.56 |

参考软件上拖后胸骨等结构显著隐去，下拖后软组织大幅显露；当前实现变化较小。
当前 CT 灵敏度直接使用 `min(1000,max(100,WW))`，AAA 的有效 WW 只有 276.18，
故 10% 拖动只改变约 27.6 HU。参考软件没有显示对应的数值或曲线，
因此本轮只确认方向和视觉响应差异，不倒推出其精确调窗公式。
代码位置：`src/qt_dicom_viewer/core/volume_view.py:77`。

## 投影差异

小赛看看菜单明确选中透视，当前渲染相机固定 `ParallelProjectionOn()`。
透视会改变不同深度结构的相对大小；正交投影也有合理用途，不能仅因不同就认定哪方几何错误。
诊断脚本用相同体数据额外输出透视版本来观察此因素，但未修改产品的相机模式。
后续应添加可选透视/正交模式，并在一致模式下复查画面。
